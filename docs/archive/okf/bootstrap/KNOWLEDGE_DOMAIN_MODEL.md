# OKF Knowledge Domain Model

**Document status:** Proposed bootstrap domain registry  
**Owner:** Knowledge Governance Owner; individual domains use the named product roles  
**Last updated:** 2026-07-31

The domain model organizes knowledge; it does not imply that corresponding
production components exist. Product Phase 2 adds Level 1/2 evidence for one
identified experimental slice; affected implementation domains may therefore be
`PARTIAL`. Only documentary/governance facts and the bounded evidence records
explicitly named below are `VERIFIED`.

## Relationship rules

- Parent/child expresses knowledge organization, not source-code containment.
- `depends-on` must name the upstream domain and the kind of dependency.
- Cross-domain behavior receives one owning domain and typed consumer relations;
  it is not copied into several competing authorities.
- Current status is evaluated per node after activation. A domain may contain
  `VERIFIED` governance nodes and `PLANNED` implementation nodes.
- New domains require a unique ID, purpose, owner, authority, dependencies,
  activation phase, and migration/validation update.

## Current conclusion

Every implementation domain lacks Level 1 evidence because implementation has not
started. This is expected, not a defect. Architecture, database, secrets, API,
privacy, packaging, platform, operations, and canonical evidence registries are
also blocked by named decisions or prerequisites. No such domain is marked
implementation-`VERIFIED`.
